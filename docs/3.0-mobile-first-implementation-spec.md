# Straw Hat Studio 3.0 — Mobile-First Implementation Specification

**Status:** Approved product direction / implementation blueprint  
**Repository:** `AnkitSharm20/StrawHatStudio`  
**Target branch:** `redesign/experience-v4` (existing redesign workstream)  
**Production:** `https://straw-hat-signal.vercel.app/`  
**Backend:** Existing Supabase project only  
**Product direction:** Hybrid Grand Line + New World  
**Navigation:** Mobile bottom tabs  
**Anime Moments:** In scope  
**PWA:** In scope  
**Desktop:** Adaptive, separately composed layout

---

## 1. Product objective

Transform Straw Hat Studio into a mobile-first anime community product that feels like a carefully designed native mobile app while remaining a complete, polished desktop experience.

This is a redesign and product evolution of the existing application, not a second website. Preserve the existing production domain, GitHub repository, Supabase project, authentication identities, user data, payment records, storage assets and working integrations. Do not create a replacement Supabase project, duplicate production app, or parallel user/account system.

The mobile experience is the primary design target. Desktop is an intentional adaptive composition, not a stretched phone layout.

### Product principles

1. Mobile-first, thumb-friendly and fast on mid-range Android devices and constrained networks.
2. Content and community before decoration.
3. One coherent design system across all routes.
4. Every visible action must work, have a clear disabled state, or be explicitly marked Coming Soon.
5. Server-authoritative security, ownership, rewards and payments.
6. No forced audio, autoplay sound, deceptive progress, fake balances or unverified purchase success.
7. Preserve accessibility, reduced-motion preferences and readable contrast.

## 2. Approved visual direction

Combine the editorial identity of **Grand Line** with the usability of **New World**, with restrained oceanic atmosphere from Thousand Sunny.

### Visual language

- Core surfaces: warm paper/ivory for selected editorial surfaces, ink/charcoal for primary dark surfaces.
- Accent: vermilion red for primary actions and important states.
- Secondary accent: muted moss/sea-glass; use sparingly.
- Optional atmospheric ocean/navy surfaces for media, featured areas and selected immersive moments.
- Typography: retain the existing Space Grotesk / DM Serif Display direction where appropriate; standardize hierarchy and remove conflicting legacy font rules.
- Avoid generic blue/purple glow, excessive glassmorphism, oversized rounded cards, excessive gradients and decorative motion without purpose.
- Provide dark and light themes with tested contrast and consistent component states.

### Design tokens

Create one source of truth for:
- Color roles: canvas, surface, elevated surface, text, muted text, border, primary, secondary, success, warning, danger, focus.
- Typography: display, page title, section title, body, metadata, button and caption.
- Spacing: a consistent 4px-based scale.
- Radii: compact controls, cards, media and modal surfaces.
- Elevation: subtle border/shadow levels.
- Motion: short interaction, page transition and optional ambient motion durations.
- Breakpoints and content widths.
- Image aspect-ratio presets and focal-position rules.

Do not append another stylesheet override layer. Consolidate overlapping CSS after verifying actual selectors and route usage.

## 3. Responsive behavior and layout contract

### Primary test widths

- Small phones: 320–359 CSS px.
- Standard phones: 360–389 CSS px.
- Large phones: 390–430 CSS px.
- Small tablets: 600–767 CSS px.
- Large tablets/small laptops: 768–1023 CSS px.
- Desktop: 1024–1439 CSS px.
- Wide desktop: 1440 CSS px and above.

### Mobile rules

- Single-column content as the default.
- Bottom navigation with safe-area inset support.
- Top app bar with contextual title, search, notification and account actions.
- Main content must not be hidden behind fixed navigation.
- Touch targets generally 44–48px minimum.
- Inputs must remain visible above the software keyboard.
- Avoid horizontal page overflow; use horizontal carousels only for deliberately scrollable content.
- Respect portrait and landscape orientation.
- Use sticky controls only where they improve the task.
- Support Android browser UI resizing, device notches and safe-area insets.

### Desktop rules

- Adaptive top navigation and optional side navigation where useful.
- Wider editorial grids and multi-column layouts.
- No forced mobile bottom bar on desktop.
- Keep content max-widths readable; avoid stretching text and cards across ultrawide displays.
- Preserve keyboard navigation and hover affordances without making hover essential.

### Media ratios

- 16:9: desktop hero/video, landscape feature media.
- 9:16: Anime Moments, vertical artwork and mobile story surfaces.
- 4:5: editorial/feed artwork.
- 3:4: anime posters.
- 1:1: avatars, icons and compact product thumbnails.
- 3:2: editorial landscape cards.

Use `object-fit: cover` only where cropping is intended, set focal positions, provide `contain` for artwork that must remain fully visible, and never stretch images. Prefer responsive image variants, modern formats, intrinsic dimensions and lazy loading below the fold. Do not describe assets as 4K unless the source actually has that resolution.

## 4. Information architecture and navigation

### Mobile bottom tabs

1. **Home** — personalized dashboard.
2. **Explore** — anime discovery and search.
3. **Crew** — community feed and rooms.
4. **Shop** — marketplace.
5. **Profile** — personal identity and collections.

Top app-bar actions: global search where relevant, notifications with unread count, and contextual account actions.

Settings, Membership, Donations, Earn Coins, Watchlist, Help and legal pages remain accessible through profile/account navigation or relevant contextual entry points. Do not overload the five primary tabs.

### Route policy

Audit the actual React Router route table before changing it. Keep stable URLs for working destinations. For incomplete destinations such as Whitelist, For You and Schedule:
- Remove them from primary navigation and homepage shortcuts.
- Route legacy URLs to a consistent Coming Soon page or an intentional redirect.
- Do not show a fake working page.
- Do not delete a route that is still used by an integration or external link without checking references first.

## 5. Page-by-page product requirements

### Home
- Personalized welcome, account shortcuts and announcements.
- Editorial featured hero with separate desktop landscape and mobile portrait artwork.
- Featured anime, trending discussions, community highlights and events.
- Marketplace highlights and membership promotion in restrained placements.
- Configurable/reorderable or hideable sections where practical.
- Real data states: loading, empty, error, retry and offline.
- Video is optional, muted by default, user-controlled and never required for page rendering.

### Explore
- Search-first discovery, genre/category filters and sorting.
- Anime detail route with synopsis, genres, artwork, external source attribution where needed, and related community discussions.
- AniList integration with caching, pagination, request deduplication, rate-limit handling, cancellation and clear retry states.
- Do not hardcode a tiny catalogue as if it were live discovery data.
- Empty and no-result states with useful recovery actions.

### Anime detail and personal tracking
- Watchlist add/remove with clear sync state.
- Personal lists and favourites.
- Avoid claiming official watch progress or streaming availability unless a verified provider supports it.
- Respect source API attribution and terms.

### Crew / Community
- Feed with post creation, edit, delete, reactions, replies, image upload and share.
- Follow/unfollow only if the backend model and authorization are implemented.
- Report, block, moderation queue and administrator actions.
- Topic-based Crew Rooms with room membership, pinned information and moderation.
- Polls, events and announcements.
- Pagination/infinite loading with duplicate prevention.
- Enforce permissions and content ownership through Supabase RLS and server-side validation.

### Anime Moments (new)
- Dedicated vertical 9:16 feed for original community artwork, permitted fan edits, memes and user-submitted media.
- Swipe/scroll navigation; never make swipe the only way to navigate.
- Like, comment, save, share, report and creator profile actions.
- Upload validation for MIME type, file size, dimensions and media duration.
- Moderation and copyright-report process before broad distribution.
- No unlicensed anime episode/clip hosting. Only content users have rights to upload and distribute.
- Lazy-load media; pause offscreen video; mute by default; offer captions where applicable.
- Provide a low-data mode and static-image fallback.

### Profile
- Avatar and cover editor with explicit crop/preview and correct aspect handling.
- Display name, username, bio and optional status.
- Streaming Luffy profile status as an optional presentation feature, not a claim of Discord custom status.
- Badges, achievements, collections, activity and membership state.
- Privacy controls for profile visibility and displayed activity.
- Owned inventory and purchase history.
- Public profile preview and shareable profile link.
- Ensure users can edit only their own profile; privileged moderation changes are audited.

### Settings
Organize into searchable groups:
- Account and profile.
- Appearance and themes.
- Notifications and push preferences.
- Privacy and visibility.
- Security, sessions and recovery.
- Connected accounts.
- Accessibility and reduced motion.
- Data, export and account deletion.
- Help, policies and app information.

Persist user settings to the existing Supabase user settings model where supported, with clear local fallback only for non-sensitive preferences. Show sync errors rather than silently implying a save.

### Marketplace
- Search, category filters, product detail, wishlist, cart/checkout as supported.
- Clear price, currency, entitlement, renewal and refund terms.
- Product artwork, inventory and ownership state.
- Order history and transaction details.
- Redeem codes with expiry, limits and server-side validation.
- No fake inventory or client-authoritative ownership.
- Keep ShopArtwork rendering and product loading/error/retry states covered by tests.

### Membership and Donations
- Dedicated mobile plan comparison with readable terms.
- Actual prices, billing interval, renewal/cancellation and entitlements.
- Donation checkout, verified donation history and receipts/status.
- Razorpay stays in Test Mode until end-to-end test cases pass and the owner explicitly authorizes live activation.
- Do not change payment secrets or live-mode configuration as part of visual work.

### Notifications
- Dedicated inbox with unread count, mark-read, mark-all-read where supported, and sensible grouping.
- Real-time updates must clean up subscriptions correctly.
- Respect notification preferences and avoid duplicate notifications.

### Admin
- Separate protected administration experience.
- Server-enforced role checks; never trust client-only admin flags.
- Manage homepage artwork, video, announcements, products, content moderation and reports.
- Audit sensitive actions.
- Admin preview must not expose privileged data or actions to ordinary users.

### Coming Soon
- One reusable page/template for genuinely unfinished features.
- Explain that the feature is not available yet.
- No fake buttons, dead-end links or invented launch dates.

## 6. Authentication and account reliability

Preserve the existing Supabase Auth project and user identities.

- Dedicated Sign In, Sign Up, password recovery and email verification screens.
- Google, GitHub and Discord OAuth only; Apple and Microsoft remain removed per prior product decision.
- Horizontal provider buttons with authentic provider marks and a consistent inline “Continue with” treatment.
- Correct OAuth callback, PKCE and redirect allow-list handling.
- Persistent session and automatic token refresh.
- No focus/visibility session polling that races PKCE or token refresh.
- Refresh/reopen/navigation tests must verify that users remain signed in.
- Handle expired sessions, revoked credentials and sign-out clearly.
- Profile bootstrap must be idempotent and must not create duplicate profile rows.
- Password feedback, rate limiting and breached-password mitigation must not falsely claim equivalence to Supabase's native leaked-password protection.

## 7. PWA specification

Implement an installable Progressive Web App using the existing Vite application.

- Web app manifest with product name, short name, theme/background colors, start URL and standalone display.
- Proper icon set including maskable icons; do not use a random placeholder as the production brand mark.
- Service worker with versioned cache strategy.
- Cache static shell/assets safely; do not blindly cache private account, payment, wallet or admin responses.
- Offline fallback that clearly indicates offline state and never fabricates fresh account/payment data.
- Update prompt that explains when a new version is ready; avoid silently breaking an active session or unsaved form.
- Install prompt only when browser support and install criteria are met.
- Push notifications are optional and require explicit permission; do not prompt immediately on first visit.
- Test install, launch, update, offline, cache invalidation and sign-out behavior on Android Chrome and desktop browsers.
- HTTPS required in production.

## 8. Media, motion, sound and loading

### Loading
- Remove artificial minimum wait and fabricated linear progress.
- Show progress only when it reflects actual work; otherwise use a lightweight branded indeterminate state.
- One short, controlled animation cycle; no repeated loop masquerading as progress.
- Use page-level skeletons after initial startup.
- Avoid blocking the entire app while nonessential API requests load.
- Respect reduced-motion and low-performance preferences.

### Music and video
- Optional music player with play/pause, volume and mute.
- Never autoplay audio.
- Video is user initiated or explicitly muted; pause when offscreen or hidden.
- Admin-managed homepage media with image fallback.
- Responsive 16:9/9:16 sources and poster images.
- Respect data saver and reduced motion.
- Use licensed, public-domain or original media with distribution rights.

## 9. New engagement features

Prioritize these after core app reliability:
- XP and levels based on legitimate community participation.
- Achievement badges and profile showcases.
- Anime quizzes and polls.
- Events and community challenges.
- User collections and shareable lists.
- Saved posts and bookmarks.
- Custom profile frames, backgrounds and themes.
- Daily rewards only with server-side limits, idempotency and audit trail.
- Crew leaderboards with anti-spam/anti-abuse safeguards.

Avoid pay-to-win mechanics, gambling-like reward loops and rewards for meaningless repeated actions.

## 10. Backend, security and integrations

Use the existing Supabase project and schema as the source of truth. Before any schema change, inspect existing tables, constraints, indexes, RLS policies, functions, storage buckets and migrations.

- Add migrations only for a demonstrated requirement.
- Preserve applied migration history; do not edit already-applied migrations.
- Enforce RLS for every user-owned table.
- Use server-side validation for payments, rewards, ownership, roles and redeem codes.
- Validate upload type, size, ownership and storage path.
- Rate-limit sensitive endpoints.
- Use idempotency for payment webhooks and reward claims.
- Verify Razorpay signatures and webhook events server-side.
- Never expose service-role keys or payment secrets in browser bundles.
- Keep audit logs for administrative and financial operations.
- Maintain API timeouts, cancellation, retry backoff and error telemetry.
- Review index usage over representative traffic before removing any index.

### Existing integrations to preserve and verify
- Supabase Auth, database, storage, realtime and Edge Functions.
- AniList discovery API.
- Discord OAuth and existing bot/Rich Presence companion boundaries.
- Razorpay Test Mode and existing payment webhook flow.
- Existing Ahrefs analytics snippet unless owner explicitly asks to remove it.

Do not claim Discord Rich Presence is the same as Discord Custom Status. Do not claim payments work until a real test transaction has been verified end to end.

## 12. Accessibility and performance targets

- Keyboard and screen-reader accessible navigation and dialogs.
- Visible focus, semantic headings, form labels and useful error announcements.
- Contrast checked for both themes.
- Reduced-motion support.
- Image dimensions reserved to prevent layout shift.
- Lazy-load offscreen images and media.
- Split routes and defer noncritical features.
- Cache public discovery data with explicit freshness; never cache private financial/account state as public.
- Avoid duplicate requests and realtime subscription leaks.
- Test on a mid-range Android device and throttled mobile network.

Use Core Web Vitals as release measurements, not guarantees. Target good field performance where possible: LCP <= 2.5s, INP <= 200ms and CLS <= 0.1 at the 75th percentile.

## 14. Acceptance criteria

A feature is complete only when the implementation and its failure states are tested.

### UX and responsive
- No horizontal overflow at supported widths.
- No overlapping, clipped or hidden controls.
- Bottom navigation respects device safe areas and does not cover content.
- All image/video ratios and crops are correct.
- Mobile forms remain usable with keyboard open.
- Desktop has a distinct adaptive layout.
- Reduced-motion and light/dark themes work.

### Functionality
- Every visible CTA has a working action or explicit Coming Soon state.
- Auth, recovery, OAuth and refresh/reopen session persistence pass.
- Profile/settings changes persist and show sync failures.
- Community post, reply, edit, delete, report and block permissions pass.
- Anime Moments upload, playback, moderation and reporting pass.
- Marketplace ownership and order history are server-authoritative.
- Notifications and unread count are accurate.
- Admin routes and mutations reject unauthorized users.

### PWA
- Installs on supported Android and desktop browsers.
- Offline fallback is clear and does not display stale private data as current.
- Update lifecycle does not discard unsaved work.
- Push permission is requested only after user intent.

### Security and release
- No service-role/payment secrets in client output.
- RLS and Edge Function permissions verified.
- Payment webhook signature, replay and idempotency tests pass.
- No critical/high unresolved release-blocking security issues.
- Build and automated tests pass.
- Vercel deployment and runtime health are verified.
- Production smoke tests pass on the existing domain.

## 16. Non-goals and prohibited shortcuts

- No second production website, duplicate Supabase project or replacement user database.
- No force-push, blind merge or production deploy to bypass conflicts.
- No mass deletion of indexes or data.
- No fake loading progress, fake online status, fake purchases or client-side wallet balances.
- No autoplay sound or forced background video.
- No unauthorized anime streaming or unlicensed content distribution.
- No hidden dead buttons, placeholder forms presented as functional, or unfinished routes in primary navigation.
- No claim of complete QA without test evidence.
